What we have learned

Rules for picking tasks

Partial credit is where most points are

q counts each goal predicate the robot newly satisfies. Tasks 56 and 42 scored with zero completions. Every all-or-nothing task we tried without a strong starting checkpoint scored 0.

Short horizons win

Everything we have scored has a human demo under ~6,500 steps. Tasks 46 (7,680) and 99 (7,739) scored 0 and 0.036.

A task the 2025 winner already trained is a head start

Our best task, task 1 (0.567), started from the winner's checkpoint_2, which already knew the task. Tasks 0–49 have such checkpoints; 50–99 start from the 50-task generalist.

The last checkpoint is not always best

Task 89 scored 0.30 at step 8000 vs 0.15 at 9999 on the same instances; task 99's retrain improved at every checkpoint instead. Choose the checkpoint on test instances 311–320, then report the leaderboard instances 301–310.

Which tasks pay partial credit

Goal predicates after expanding each task's BDDL goal the same way the official scorer does. Orange ticks are goals the robot can still earn; grey ticks are goals already true at reset, which count in the denominator but can never pay. Click a column to sort.

Method. Goals are grounded from BEHAVIOR-1K bddl3 activity definitions (problem0.bddl) with get_ground_goal_state_options, the options omnigibson/metrics/task_metric.py scores. Per-instance q = goals newly satisfied ÷ total goals (max over grounding options), or 1.0 on success. "Goals already true at reset" is judged from each problem's :init only, so treat it as approximate.

Demo steps are mean human demo lengths from the 2026 task metadata; the eval time limit is 1.5× that. Scores are from our local evals, computed like the leaderboard (instances 0–9 = 301–310, one rollout each, sum ÷ 10); they are not yet submitted. Until 29 Sep this page averaged all 20 public instances, which gave 0.0172 overall.
