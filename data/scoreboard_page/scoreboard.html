What we have learned

Rules for picking tasks

Partial credit is where most points are

q counts each goal predicate the robot newly satisfies. Tasks 56, 10 and 42 scored with zero completions. Every all-or-nothing task we tried without a strong starting checkpoint scored 0.

Short horizons win

Everything we have scored has a human demo under ~6,500 steps. Tasks 46 (7,680) and 99 (7,739) scored 0.

A task the 2025 winner already trained is a head start

Our top two, task 1 (0.517) and task 40 (0.350), both started from a winner checkpoint that already knew the task. Tasks 0–49 have such checkpoints; 50–99 start from the 50-task generalist.

The last checkpoint is not always best

Task 89 scored 0.30 at step 8000 vs 0.15 at 9999 on the same instances. Screen several checkpoints on 5 instances, then run all 20 on the winner.

Which tasks pay partial credit

Goal predicates after expanding each task's BDDL goal the same way the official scorer does. Orange ticks are goals the robot can still earn; grey ticks are goals already true at reset, which count in the denominator but can never pay. Click a column to sort.

Method. Goals are grounded from BEHAVIOR-1K bddl3 activity definitions (problem0.bddl) with get_ground_goal_state_options, the options omnigibson/metrics/task_metric.py scores. Per-instance q = goals newly satisfied ÷ total goals (max over grounding options), or 1.0 on success. "Goals already true at reset" is judged from each problem's :init only, so treat it as approximate.

Demo steps are mean human demo lengths from the 2026 task metadata; the eval time limit is 1.5× that. Scores are from our local evals on the 20 public instances (301–320), not leaderboard submissions.
